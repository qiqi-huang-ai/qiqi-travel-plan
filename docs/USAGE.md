# 使用 Travel Plan Pro

## 安装

下载仓库后，将文件夹命名为 `travel-plan-pro`，放到当前项目的 `.codex/skills/` 目录。保留 `SKILL.md`、`references/`、`scripts/` 与 `assets/` 的原有目录结构。

需要从命令行验证或渲染示例时，请准备 Python 3.10 或更新版本；核心脚本只使用 Python 标准库。

## 第一次规划

可以直接用自然语言说明旅行需求。尽量提供出发地、日期或天数、同行人、预算、交通偏好、节奏、必去点、已订安排和期望交付形式；没有确定的项目可以明确说“未定”。

```text
从杭州出发，11 月周末想玩两天一晚，两位成人，总预算 2500。
不自驾，想逛老街和吃小吃，连续步行别超过 1 小时；酒店和车票都没订。
请先比较三个方向，再把我选的目的地做成 Markdown 和离线 HTML。
```

如果日期与“几天几晚”的说法矛盾，或必去点与体力、交通、预约前提冲突，Skill 会说明冲突并请你选择，不会静默改写条件。

## 先选择数据能力

在调研前，Skill 会先问是否接入 TikHub。选择只影响公开小红书体验线索，不影响基础行程交付。

| 选择 | 适合什么情况 | 结果 |
| --- | --- | --- |
| `本次不接入` | 只需基础方案，或不希望产生第三方 API 请求。 | 继续普通调研，并注明社媒体验覆盖较薄。 |
| `接入已有配置` | 本机已安全配置好 TikHub，且愿意给本次请求设置预算。 | 在明确预算内查询、记录用量，并把结果作为体验线索。 |
| `需要配置指导` | 想先了解价值、成本与配置步骤。 | 只做说明，不索要密钥，也不会发出真实请求。 |

不要在聊天、`trip.json`、输出 HTML 或日志里粘贴 Token。真实请求只读取本机环境变量，并要求明确的预算上限。详见 [TikHub 说明](../references/tikhub.md)。

## 会交付什么

- `trip.json`：唯一业务源，保存需求、约束、来源、事实状态、预算、版本与复查队列。
- Markdown：适合阅读、讨论与存档。
- 单文件 HTML：可下载后双击离线打开；有分区导航、按天筛选与本地保存的清单进度。
- manifest 与可选复查队列：用于确认同一版本的输出是否完整，以及出发前还应核查什么。

已生成的通用示例可在 [示例目录](examples/) 查看。示例地点和来源均为虚构数据，只用来验证交付形式。

## 修改与出发前复查

不要直接改旧版本输出。修改需求后，应保存一个新版本、使受影响的证据失效、重新核查依赖项，再渲染新的 Markdown 与 HTML。临近出发可用 `recheck_trip.py` 生成可执行的复查队列；完整生命周期规则见 [lifecycle.md](../references/lifecycle.md)。

## 验证公开包

在 Skill 根目录运行：

```bash
python3 scripts/release_check.py
```

它会检查公开包所需文件、示例链接、Python 3.10 语法和行为测试。此检查不代表外部 API 实际可用，也不替代对目标日期的开放、预约、票价、路线或天气核验。
